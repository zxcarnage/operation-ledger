# Локальный стенд и разбор сбоев

## Приложение не запускается

1. Проверить docker compose ps и логи postgres/kafka. Убедиться, что порты 5432, 9092, 8081 и 8080 свободны.
2. Проверить DB_URL и KAFKA_SERVERS. В контейнере localhost указывает на сам контейнер; приложение из Compose использует postgres:5432 и kafka:19092.
3. Если Flyway сообщил checksum mismatch, найти причину изменения применённой миграции. Для следующего изменения схемы добавлять новый файл V3, не переписывать V1.
4. Если mvn verify сообщает Could not find a valid Docker environment, проверить docker version. Docker Engine должен быть запущен. Для Docker 29 используется Testcontainers 1.21.4: версия 1.21.3 не подходит.

## Повторная регистрация вернула 409

Сопоставить Idempotency-Key с request_id. Сравнить accountId, amount, currency и description. При таймауте клиент обязан сохранить исходный ключ и повторить исходные данные. Генерация нового ключа при каждом retry создаёт новые операции.

## Статус не изменился после Kafka

Проверить сообщение в operation-status-commands: валидны ли UUID, reason, status и ключ operationId. Найти eventId в processed_messages, затем журнал status_history. Если маркер есть, повтор того же события уже обработан. Если его нет, проверить DLT и исключение listener.

Команды из DLT не нужно автоматически возвращать бесконечно. Сначала определить причину: устаревшая команда, неверный контракт, неизвестная операция или временный сбой БД. После исправления временного сбоя можно повторить исходное сообщение с тем же eventId: откатившаяся транзакция не оставляет маркер. Если меняется смысл события, источник должен выдать новый eventId.

## Исходящие события задерживаются

~~~sql
SELECT count(*) AS pending, min(created_at) AS oldest
FROM outbox WHERE published_at IS NULL;
SELECT event_id, operation_id, attempts, created_at
FROM outbox WHERE published_at IS NULL ORDER BY created_at LIMIT 20;
~~~

Найти в логах Outbox publish failed и eventId. Проверить доступность Kafka и права на топик. Бизнес-транзакции продолжают создавать outbox при недоступном брокере; таблица будет расти. В текущей реализации нет автоматического удаления опубликованных событий или inbox. Политику хранения нужно определить до длительной эксплуатации.

Проверять не только количество записей, но и возраст самой старой. Постоянно ошибочное событие может занимать публикатор: ручной разбор или отдельная очередь ошибок — следующая задача.

## Медленная история

Найти запрос по X-Request-Id, сравнить durationMs с http.server.requests в Actuator. Выполнить EXPLAIN (ANALYZE, BUFFERS) на той же форме запроса, проверить свежесть статистики и размер страницы. Не включать полный Hibernate SQL с параметрами надолго на рабочем окружении: логов станет много, а параметры могут содержать чувствительные данные.

## Остановка

~~~sh
docker compose --profile app down
~~~

Команда сохраняет volume PostgreSQL. Удалять volume имеет смысл только при намеренном сбросе локальной базы; это отдельное действие. Testcontainers создаёт изолированные контейнеры и удаляет их через Ryuk после тестов.
