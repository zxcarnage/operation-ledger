# Следующая итерация

Оценки предварительные, в рабочих днях одного разработчика. Это план развития проекта, а не запись о прошедшем спринте.

| Задача | Оценка | Что считать готовым |
|---|---:|---|
| Авторизация JWT и доступ к счёту | 3–4 | Проверяется issuer/audience, чужой accountId закрыт тестами |
| Cursor pagination | 2 | Курсор содержит время и UUID, новые вставки не сдвигают следующую страницу |
| Метрики inbox/outbox | 1–2 | Видны лаг, возраст старого события, повторы и DLT; есть пороги |
| Ретеншн служебных таблиц | 2 | Согласовано окно дедупликации, удаление пакетами не блокирует запись |
| Упорядоченная публикация по операции | 3 | Два экземпляра не публикуют более новую версию раньше старой |
| Контрактные тесты сервиса счетов | 2 | Несовместимое изменение ответа выявляется до релиза |
| Нагрузочный baseline | 1–2 | Сохранены входные данные, конфигурация, планы и три прогона |

Сначала закрыть авторизацию, затем наблюдаемость. Переход на CDC имеет смысл после измерения пропускной способности текущего outbox; вводить его ради количества технологий в стеке не нужно.

Для обсуждения проекта полезно уметь восстановить без подсказки два сценария: конкурентная регистрация с одинаковым ключом и падение после отправки Kafka до коммита outbox. Если эти случаи понятны, разговор на интервью быстро перейдёт от аннотаций к гарантиям системы.
